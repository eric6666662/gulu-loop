## 2. 模块划分（深模块）

分两层：**组件层是浅的**（只做渲染，逻辑不落地），**逻辑层是深的**（小接口、厚实现、可单测）。

### 2.1 逻辑模块

| 模块 | 对外接口（小） | 隐藏的行为 | 边界依据 |
|------|----------------|------------|----------|
| `lib/ndjson.ts` | `readNdjson(res: Response, onEvent: (e: StreamEvent) => void): Promise<void>` | 分块解码、按 `\n` 切行、**跨 chunk 的半行缓存**、CRLF、空行跳过、坏行跳过、`done`/`error` 后停止读取 | 纯函数式，喂字符串就能测；流式协议的唯一解析点 |

## 3. 状态管理

**不引 Pinia**（ADR-0002）。数据形状决定方案：全部是**服务端拥有的状态**（会话、消息、服务商），没有需要跨路由共享的客户端状态，单视图。

| 状态 | 放在哪 | 谁写 |
|------|--------|------|
| `conversations`（分页列表） | `useConversationList()` 实例，`App.vue` 创建 | 列表自身（loadMore / create / remove / rename / touch） |
| `selectedId` | `useSelectedFromQuery(items)` 返回的 `ref`，`App.vue` 持有 | 侧栏 emit `select` / 新建后自动选中 / 删除后迁移 / **URL 的 `?c=` 变化**（双向：读初始化 + 写回地址栏） |
| `messages` + `status` + `model` | `useChat(selectedId)`，`ChatArea.vue` 创建 | 聊天自身（send / stop / retry / edit / refresh） |
| `providers` | `useProviders()` 实例，`App.vue` 创建后 `provide` | 服务商设置视图（create / update / remove / test）；`ModelPicker` / 落款行只读 |
| `pane` / `step` / `editing` | `useSettingsPane()` 实例，`App.vue` 创建后 `provide` | 侧栏 ⚙、列表页（✎ / 添加 / 返回聊天）、编辑页（保存 / 取消）——都只调它的 6 个方法 |
| 弹层开合、`pickerOpen`、`draft`、toast 队列 | 各自组件本地 `ref` | 组件自己 |
| `models` / `hasMore` / `currentConversation` | **不存**，`computed` 派生 | — |

**跨组件共享只有两条**：① `providers` 从 `App.vue` 用 `provide('providers', ...)` 下给 `ModelPicker`、`MessageAssistant`（落款行）与 `SettingsView`；② `useSettingsPane` 同理下给侧栏与 `SettingsView`（侧栏 ⚙ 要能切 pane）。其余全部是父子 props/emit——**不新增全局 store**。

**升级触发条件**（写进 ADR-0002）：出现第二个页面 / 需要跨路由共享状态 / 需要时间旅行调试 → 再引 Pinia。

## 4. 路由

| 路由 | 页面 | 鉴权要求 |
|------|------|----------|
| `/`（唯一入口） | `App.vue` → `ChatPage`（侧栏 + 聊天区，弹层为覆盖层） | 无（单用户本地工具，01-需求 明确不做认证） |
| `/?c=<conversationId>` | 同上，**当前会话由查询参数决定** | 无 |

**MVP 不引 `vue-router`**：单视图，弹层不需要独立 URL。当前会话用 `useSelectedFromQuery(items)` 的 `selectedId` 表示，**并同步到地址栏的 `?c=<id>`**——不是路由，只是查询参数。

**深链规则**（`composables/useSelectedFromQuery.ts` 一个模块兜住）：

| 场景 | 行为 |
|------|------|
| URL 无 `?c=` | 选中 `items[0]`（最新会话），并**不**写参数（保持地址干净） |
| URL 有 `?c=` 且 id 在列表里 | 选中它 |
| URL 有 `?c=` 但 id 不存在 / 会话已被删 / 首次加载时列表还没到 | 回落 `items[0]`，并用 `replaceState` **清掉无效参数**（不留死链） |
| `selectedId` 为 `''`（草稿态） | 右侧显示**默认对话页**；`?c=` 被清掉（`select('')` 写 `null`）。草稿态不请求后端、不进列表（01-需求 #5b） |
| 用户切换会话（点侧栏、新建、删除后迁移） | `selectedId` 变 → `history.replaceState` 回写 `?c=<id>` |

**必须用 `replaceState`，不能用 `pushState`**：否则每切一次会话就往浏览历史塞一条，后退键会变成"退回上一个会话"，越用越乱。目标效果是"后退键离开咕噜，而不是在会话之间来回"。

**服务商设置不是路由，是主区的第二个视图**（ADR-0012）：`pane: 'chat' | 'settings'` 由 `useSettingsPane()` 管，`ChatArea` 与 `SettingsView` 用 `v-if` 互斥。理由：单用户本地工具，设置页不需要可分享的 URL；引 `vue-router` 只为一个开关，等于给单页工具加一层路由表 + 懒加载 + 守卫的样板。代价是**设置页没有深链、刷新会回到聊天**（可接受：设置是低频操作）。

- 未来加路由的触发条件：出现**第三个**主视图 / 多模块（Agent、知识库）导航时再引 `vue-router`，届时 `pane` 升级为 `/settings`、`?c=` 升级为 `/c/:id` 正式路由（`useSettingsPane` / `useSelectedFromQuery` 内部换成 `useRoute`/`useRouter`，组件层不用改）。

## 5. API 消费

后端响应统一信封 `{code, message, data}`，`code` 即 HTTP 状态码（`internal/httpapi/respond.go`）。前端在 `api/client.ts` 一次性拆封，`code != 200` 抛 `ApiError(message)`，`message` 直接可展示（后端已写中文）。

| 接口 | 关键字段 | 错误处理 | 契约状态 |
|------|----------|----------|----------|
| `GET /api/v1/conversations?page=&pageSize=` | `id`、`title`、`lastMessageTime`、`messageCount` | 空列表 → 侧栏空态；失败 → 列表区错误行 + 重试 | 已对齐（`messageCount` 来自 `x_conversations.message_count` 冗余列，ADR-0007） |

## 6. 数据流

**首屏**
```
main.ts → App.vue
  ├─ useProviders()      → GET /service-providers  → providers / models
  ├─ useSettingsPane()   → pane='chat'（侧栏 ⚙ 才会切到 settings）
  └─ useConversationList() → GET /conversations      → items（10 条）
        └─ useSelectedFromQuery(items)：读 ?c= → 校验 → selectedId（无效则 items[0] + 清参）
              └─ ChatArea → useChat(selectedId) → GET /conversations/{id}/messages
                    └─ MessageList 渲染（按 seq 升序）
```
任一步失败：该区域进错误态（列表区一行 / 消息区错误卡），不阻塞其他区域。

**发送消息（流式）**
```
Composer --emit send(text)--> useChat.send()
  ├─ 乐观：messages.push({role:'user', content})      → 立即渲染
  ├─ api/messages.send({convId, content, model}) → fetch(POST …/messages)
  │     └─ lib/ndjson.readNdjson(res, onEvent)
  │           ├─ start → status='streaming'，插入空 assistant 占位
  │           ├─ delta → 追加 content（TypingIndicator 常驻）
  │           ├─ done  → status='idle'，落款行出现 model + 时间
  │           └─ error → status='error'，StreamError 插在末尾（不写库）
  ├─ stop() → controller.abort() → 保留已收内容，status='idle'
  └─ 结束后 useConversationList.touch(convId) → 更新列表时间与消息数（本地，不重拉）
```

**重试 / 编辑后重发**：`useChat.retry(msgId)` / `useChat.edit(msgId, newContent)` → 本地截断该消息及其后 → 复用 `send()`（带 `messageId` 或新内容）→ 同上流式链路。

**切换会话**：侧栏 `select(id)` → `App.selectedId` 变 → `ChatArea` 的 `watch` 触发 `useChat` 内部：取消在途请求 → `GET messages` → 清空错误态。

**删除会话**：`ConversationItem ×` → `ConfirmDialog` → `useConversationList.remove(id)` → 列表移除 → 若删的是当前会话，选中下一条（无则空态）。

**草稿态 → 首条消息（01-需求 #5b）**
```
点「新的聊天」--select('')--> selectedId=''（纯前端：不请求后端、不插列表项、清空输入框）
  └─ 右侧 ChatArea(conversationId='') → 草稿对话页（EmptyState 变体 + 输入框可用）
        └─ Composer --send(text)--> useChat.send()
              ├─ selectedId==='' → 先 POST /conversations 拿 id（App 注入的 ensureConversation()）
              │     └─ 成功后：select(id) + 侧栏插入该项（标题由后端按首条消息生成）
              └─ 再 POST /conversations/{id}/messages（NDJSON 流式，任务 6）
失败：会话已建但消息没发出去 → 保留这个 0 条消息的会话，toast 提示可重试/删除
```

**首条消息后拿自动标题（01-需求 #10）**
```
useChat.send() --done--> ChatArea emit done(convId, messageCount)
  └─ App.onChatDone：list.touch(id, {messageCount, lastMessageTime})
        └─ 若该会话 title 仍为空 → list.loadFirstPage()
              （后端在首条 user 消息写入时生成了标题，前端只能重拉才拿到；
                顺带把新会话按 lastMessageTime 排到最前）
```

**服务商设置（列表页）**
```
侧栏 ⚙ --openSettings()--> useSettingsPane.pane = 'settings'
  └─ SettingsView（step='list'）
        └─ ProviderList : providers（来自 useProviders，App.vue 注入）
              ├─ 行尾 ✎      --editProvider(p)--> step='edit'，editing=p
              ├─ 右上「添加服务商」--createProvider()--> step='edit'，editing=null
              ├─ 行尾 ⋯ → 检测连通 --useProviders.test(name)--> 200 → toast 正常 / 502 → toast 危险（bg-danger）
              ├─ 行尾 ⋯ → 删除     --> ConfirmDialog（服务商版）--> useProviders.remove(name)
              └─ 「返回聊天」  --closeSettings()--> pane='chat'（聊天状态与在途流不受影响）
```

**服务商设置（编辑页）**
```
ProviderDetail（step='edit'，editing=null 时标题为「添加服务商」）
  ├─ 基本信息：名称(只读) / 官网链接 / Base URL / api_key（留空 = 不改）
  ├─ 「拉取模型列表」--fetchModels({serviceProvider?, baseUrl, apiKey?})--> ModelFetchDialog
  │     └─ 勾选 → confirm(ids) → 追加到本地 models（重复跳过，**不落库**）
  ├─ ModelRow × n：默认单选 / 标识 / 展示名 / 删除 → 只改本地表单副本
  ├─ 「保存服务商」--> create/update --> 成功后 providers 变 → models 自动重算 → 回列表页
  └─ 「← 服务商列表」/「取消」--> backToList()（**丢弃未保存改动**，见待确认 10）
```

> 编辑页一律**改本地副本**（`editing` 的浅拷贝），点保存才提交——拉取失败、校验失败都不会污染 `providers`。

## 7. 测试边界

按"通过接口测，不测内部实现"：逻辑模块给单测，组件只测**交互契约**（emit / 禁用态 / 文案），不测样式（样式由原型负责）。

| 模块 | 入口 | 典型用例 |
|------|------|----------|
| `lib/ndjson` | `readNdjson(fakeResponse, spy)` | ① 一行一个事件；② **一条 JSON 被切成两个 chunk** 仍能正确拼回；③ 结尾无换行的最后一行也算；④ CRLF；⑤ 坏行跳过不中断；⑥ `done` 之后不再回调；⑦ `error` 事件透传 message |
| `api/client` | `request()` + 假 fetch | ① 拆 `data`；② `code=400` 抛 `ApiError` 且 `message` 是后端中文；③ 网络异常归一化；④ 非 JSON 响应不崩 |
| `api/messages` | `send()` + 假流 | ① `{abort}` 能中断且不再回调；② 超时映射成 error 事件；③ `messageId` 透传到请求体 |
| `api/providers` | `list()` / `fetchModels()` / `test()` | ① `models` 按 `[{id,name}]` 直传，不再解析 `settingJson`；② `fetchModels` 只返回 id 数组、不发写请求；③ `test` 502 时抛 `ApiError(message)` 供危险 toast 展示 |
| `composables/useChat` | 注入假 `api/messages` | ① 发送后立即出现 user 消息；② `delta` 逐段追加；③ `error` 后状态为 error 且 assistant 不落库；④ `stop` 保留已收内容；⑤ `retry` 截断后续消息；⑥ 切会话取消在途请求 |
| `composables/useConversationList` | 注入假 `api/conversations` | ① 首屏 10 条；② `hasMore` 翻页；③ 首屏未填满自动补一批；④ 删除后选中项迁移；⑤ `touch` 只改本地时间与计数 |
| `composables/useProviders` | 注入假 `api/providers` | ① `models` 去重且带服务商名；② 增删改后 `models` 自动重算；③ `test()` 原样返回 `{ok, latencyMs, modelCount}` 且**不自己弹 toast**；④ `remove()` 成功后该服务商的模型从 `models` 里消失 |
| `composables/useSettingsPane` | 直接调用 | ① 初始 `pane='chat'`；② `openSettings()` → `pane='settings'` 且 `step='list'`；③ `editProvider(p)` → `step='edit'` 且 `editing=p`；④ `createProvider()` → `step='edit'` 且 `editing=null`；⑤ `backToList()` / `closeSettings()` 复位 |
| `composables/useSelectedFromQuery` | 传入 `items` ref + 假 `location` | ① 无参数 → 第一条且不写地址；② 有效 `?c=` → 对应会话；③ 无效 / 已删除 → 回落第一条并清参；④ 切换会话 → 调 `replaceState`（**断言没调 `pushState`**）；⑤ 列表后到时 `?c=` 仍能生效 |
| `lib/markdown` | `await renderMarkdown()` | ① 代码块包了 `data-copy-code` 容器 + `pre > code` + 高亮色；② 未知语言不崩；③ 行内 code class；④ HTML 被转义（XSS）；⑤ 外链 `target=_blank` + `rel="noopener noreferrer"`；⑥ 段落/列表结构 |
| `lib/format` | `relativeTime()` | 今天 / 昨天 / 本周 / 更早 四档 + 跨月边界 |
| `Composer` | `mount` + `trigger('keydown')` | ① 空内容 Enter 不 emit；② Shift+Enter 不 emit；③ 有内容 Enter emit `send`；④ `disabled` 时发送按钮禁用 |
| `ModelPicker` | `mount` + `click` | ① 默认隐藏；② 点触发按钮展开、`aria-expanded` 同步；③ 选中 emit `update:modelValue` 并关闭；④ Esc 关闭 |
| `ConversationItem` | `mount` | ① 渲染标题 / 时间 / 「N 条消息」；② 点 × emit `delete`（不触发 `select`）；③ 当前项有 `aria-current` |
| `ProviderRow` | `mount` | ① 渲染名称 / 模型数 / 官网域名（去协议头）；② `website` 为空时不渲染链接行；③ 点 ✎ emit `edit`；④ **不渲染任何「使用中」文案或按钮**（防止回归） |
| `ProviderRowMenu` | `mount` + `click` | ① 默认关闭；② 点 ⋯ 展开且 `aria-expanded=true`；③ 点「检测连通」emit `test` 并关闭；④ 点「删除」emit `remove` 并关闭；⑤ Esc / 点外部关闭 |
| `ModelRow` | `mount` | ① 渲染标识 / 展示名；② 改标识 emit `update`；③ 点单选 emit `set-default`；④ 默认行**没有**删除按钮 |
| `ModelFetchDialog` | `mount` + `click` | ① 已添加的 id 置灰不可选；② 只 emit 勾选后新增的 id 列表（不覆盖已有）；③ 502 时展示 `message` 且不关闭弹层 |

**不做的**：E2E（Playwright）—— MVP 单页、关键链路已被 composable 单测覆盖；等出现"多页面 + 跨页流程"再引。样式快照不测（视觉契约是原型 + 截图）。
