## PR / 合并标题与描述

**标题**：`feat: 咕噜 MVP AI 聊天链路（多服务商 + 流式 + 自动摘要 + 上下文压缩）`

**描述**：咕噜（gululoop）的第一阶段交付 —— 打通「用户发消息 → 后端调 LLM → 流式输出 → 会话管理」的完整链路。Go 后端（chi + sqlx + SQLite + `openai-go` 全封装）+ Vue 3 前端（Tailwind v4，产物 `go:embed` 进二进制）。支持多服务商配置（含**激活的服务商**决定 base_url/api_key）、流式 NDJSON、会话历史、重试/编辑后重发、上下文摘要压缩、Markdown 渲染与导出。**怎么验证**：Go 99 测试函数 + 前端 237 用例全绿；端到端真浏览器验证草稿态只 1 次请求、激活切换、重试、LLM 失败保留会话。

| **UI** | 侧栏 + 聊天区 + 服务商设置（两级页面）+ 6 个弹层 | Vue 3 组件 40 个测试文件覆盖；`useChat`/`useModelSelection`/`useProviders` 等深模块 |

**Breaking Change**：

1. **`x_service_provider` 加列 `is_active`**（`000002` 迁移）—— 可回滚（`Down` 删列+索引）。
2. **`POST /conversations/{id}/messages` → `POST /api/v1/messages`**（ADR-0017）—— `conversationId` 移到 body 且可选；旧路径废弃（`GET` 列表路由不变）。
3. **流式事件改名 + 加字段**（ADR-0017）—— `start`→`meta`、`delta`→`message`；`meta` 带 `title`、`message` 带 `thinkingContent`、`done` 带 `updatedAt`、`error` 带 `conversationId`。
4. **请求体 `messageId` 拆成 `userMessageId` + `assistantMessageId`**，加显式 `type`（`send`/`regenerate`）（ADR-0017）。
5. **发送时用"激活的服务商"而非"第一个服务商"**（ADR-0015）—— Bug 修复：此前切模型仍打到第一个服务商的 base_url/api_key。

## 风险与回滚

- **难回滚项**：ADR-0017 的契约破坏性变更（路由 + 事件名 + 请求体）—— 回退要同时改后端路由/事件、前端 `api/messages`+`ndjson`+`useChat`，且 `ensureConversation`/`loadFirstPage` 两个 workaround 要加回来。实际不会退。
- **数据迁移可逆性**：`000002`（`is_active` 列）**可逆** —— `Down` 迁移删索引+列。回填逻辑升级后行为与升级前一致（`created_at` 最早 = 旧 `firstProvider`）。
- **其他风险**：
  1. `regenerate` 后 `userMessageId` 会变（原 id 已删、重追）—— 前端靠 `meta` 替换本地旧 id，若绕过 `meta` 用旧 id 会 400。
  2. 思考内容契约带、前端存、UI 不渲染（deferred）—— 数据流完整，渲染是独立后续特性。
  3. 单用户本地工具，无认证 —— 明确非目标。

## 上线动作（按顺序）

1. **数据迁移**：启动时 `dal.Migrate` 自动跑 `000002`（加 `is_active` 列 + 索引 + 回填）。无需手工 SQL。**回退**：`goose down` 到 `000001`。
2. **无配置变更 / 无密钥 / 无外部服务依赖**（`api_key` 由用户在界面配置，存在本地 SQLite）。
3. 构建：`cd web && npm ci && npm run build` → `go build -o gulu ./cmd/server`（前端产物 `go:embed` 进二进制）。
