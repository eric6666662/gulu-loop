### 2.2 图标清单（原型 sprite ↔ lucide-vue-next）

> 原型 sprite 的 14 个图标已全部换成 Lucide 官方路径，开发直接 `import { X } from 'lucide-vue-next'`，不手写 path。
> 用法：`<Bot class="size-4" :stroke-width="1.5" />` —— **Lucide 默认 stroke-width 是 2，必须显式传 1.5**（16px 下 2 会缩成 1.33px，比原型粗一档）。

| 原型 sprite | Lucide 组件 | 用在哪 |
|-------------|------------|--------|
| `i-robot` | `Bot` | 输入区模型按钮（图标 + 当前模型名） |
| `i-send` | `ArrowUp` | 发送 |
| `i-stop` | `Square` | 流式中的「停止生成」 |
| `i-retry` | `RefreshCw` | 会话头刷新、消息重试 |

## 5. 美学方向

沿用 `docs/设计稿.md`（视觉主张、色板、字阶、组件规范、文案基调）。本需求例外项：

- **例外 1 · 阅读字号与界面字号分家**：消息正文 `text-body-lg`（16/28，行高 1.75）；侧栏、按钮、表头用 `text-body`（14/26）与 `text-meta`（13/20）。
- **例外 2 · 落款行（记忆点）**：每条助手回复下常驻 `text-caption` 模型名（`deepseek-chat` / `kimi-k2`）+ 右侧时间；重试 / 复制 hover 出现、与落款同行。让"多服务商"在界面上可见。
- **例外 3 · 换模型的痕迹**：会话内换模型时插入发丝线 + 居中 `text-caption`「已切换到 kimi-k2」。真实状态编码，不是装饰。
- **例外 4 · 助手回复无容器**：不加卡片、不加气泡、不加边框；用户消息是整页唯一带底色的内容块。
- **例外 5 · 消息区铺满右侧（需求指定，优先于窄栏）**：不再居中 672px；`≥lg` 左右内边距 48px，1440 下正文行宽约 69 中文字——仍 < 80 字符的硬线，但超过我原定的 38 字舒适线，这是需求明确要求的取舍（长文阅读让位给"用满屏幕"）。
- **例外 6 · 侧栏会话项两行**：标题独占一行（截断）+ 次行「N 条消息（左）/ 时间（右）」；删除下沉为 hover 出现的 ×，不再有 ⋯ 菜单，侧栏顶部也不放按钮。
- **例外 7 · 输入区两层（上输入 / 下图标栏）**：上半是多行输入区（自动增高、超出内部滚动），下半是高度固定的图标按钮栏——左侧放模型按钮（robot 图标 + 当前模型名，文字让人一眼知道在用哪个模型），最右侧放主操作（发送），中间用 `flex gap-1` 留扩展位。切换模型的弹层**从按钮本身向上弹出**，与按钮左缘对齐，不再跑到聊天框顶上。主操作按钮一个槽位两态：空闲是上箭头（发送），流式中是方块（停止生成）——不为「停止」另开一个按钮，图标栏始终只有两个控件。
- **例外 8 · 服务商设置占满右侧主区，两级页面（v11，v12 收敛）**：不再用弹层——弹层一屏放不下连接信息 + 模型清单。改成主区整页后分两级：**列表页**（一行一个服务商，信息与操作都在行内）+ **编辑页**（整页替换，详情独立滚动、保存栏常驻底部）。两级而不是「左列表 + 右详情」，因为列表行要放 icon / 名称 / 模型数 / 官网 / 两个操作，224px 窄栏塞不下；而编辑页字段多，需要整幅宽度。**v12 又做了一次减法**：列表去掉「使用中 / 使用」、模型行去掉三个参数——判断标准是「这一列有没有消费方」，没有就砍掉。**分区用发丝线 + 小标题，不用卡片套**（卡片只留给服务商行与模型行这种"可操作的条目"）。
- 反"AI 味"与廉价感自查：无渐变、无卡片套、无 emoji、无全大写眉标、无中点串标签、无 `→` 按钮；深色底只出现在 Toast 与遮罩。

  - `<lg` 的 ☰ 放在右侧图标组末尾（不是标题左侧），否则标题会被顶出对齐线。
- **断点**：`<lg` 侧栏转覆盖抽屉（`fixed` + `-translate-x-full`，遮罩 `bg-overlay`），会话头出现 ☰；输入区提示文案 `<sm` 隐藏（模型切换与发送按钮始终可见）；`<sm` 服务商表格隐藏 Base URL，`<md` 隐藏默认模型。
- **纵向**：`h-dvh` 三段式（头 56px / 消息区滚动 / 输入区固定），页面本身不滚动；侧栏列表独立滚动。

### 6.2 关键流程

**流程 1 · 发送消息（流式）**
1. 输入框按 Enter 或点图标栏最右侧的发送按钮（Shift+Enter 换行；内容为空时两者都不动作，发送按钮此时为禁用态）。
2. 用户消息立即上屏，输入区清空并回落到单行高度，发送按钮回到禁用态。
3. 输入区禁用：`bg-surface-alt`、textarea disabled；图标栏最右侧的主操作按钮**切成「停止生成」并保持可用**；「正在生成」由消息区的 TypingIndicator 表达。
4. 消息区底部出现「kimi-k2 正在生成」，正文按 `delta` 逐段追加。
5. `done`：落款行出现模型名与时间，操作按钮可用，输入区恢复。
6. `error`：StreamError 卡片插在末尾，assistant 消息不写入。

**流程 1b · 停止生成**
1. 流式中点主操作按钮（方形图标，Tooltip「停止生成」）。
2. 前端中止本次 NDJSON 读取，已收到的内容保留为一条 assistant 消息（不写入未完成的片段）。
3. 输入区恢复可编辑，按钮回到「发送」并因空输入而禁用。
4. 原型里点停止 = `console.log('停止生成')` + 回到空闲态（不追加消息）。

**流程 2 · 重试**：hover 助手回复 → 重试 → 该回复及其后消息清除 → 以原用户消息重新发起 → toast「已重试」。

**流程 3 · 编辑后重发**：hover 用户消息 → 编辑 → 弹层预填原文 → 保存 → 该消息及其后全部清除 → 以新内容重发 → toast「已修改并重发」。

**流程 4 · 删除会话**
1. 会话项 hover → × → 确认弹层，标题「删除「<会话标题>」？」（唯一入口）。
2. 弹层正文：「这个会话里的 N 条消息会一起删掉，无法恢复。想留档就先导出 Markdown。」
3. 主按钮「删除会话」（`bg-danger`）→ 级联删除 → toast「会话已删除」；次按钮「先留着」。

**流程 5 · 新建会话**：侧栏底部「+ 新的聊天」→ 新建空会话并聚焦输入框 → toast「已新建会话」。

**流程 6 · 刷新 / 编辑标题 / 分享（会话头三个图标）**
- 刷新：重新拉取当前会话消息（不改列表）→ 进行中按钮 disabled → toast「已刷新当前会话」。
- 编辑：弹层预填标题 → 保存 → toast「已重命名」。
- 分享（图标为分享，不是下载）：把当前会话导出为 Markdown 并下载 → toast「已导出：<会话标题>.md」。

**流程 7 · 切换模型**
1. 点图标栏左侧的模型按钮（robot 图标 + 当前模型名，hover 有 Tooltip「切换模型」）→ 弹层从该按钮向上展开、与按钮左缘对齐，列出 7 个模型（主行＝模型 id，右侧小字＝服务商），当前项打勾。
2. 点某一项 → 勾选移过去、**按钮上的模型名同时换成 glm-4.6**、弹层关闭、toast「已切换到 glm-4.6」。
3. 点弹层外或按 Esc 关闭；弹层开着时不叠 Tooltip。
4. 选中后本会话后续消息带 `model` 字段；与上一条助手回复的模型不同时，消息区插入「已切换到 xxx」分隔（原型里消息内容是静态示例，不随切换变化）。

**流程 8 · 会话列表滚动加载**
1. 首屏取 10 条（`GET /api/v1/conversations?limit=10`）。
2. 滚到底（距底 ≤ 24px）→ 显示「正在加载更多会话」占位行 → 追加下一批 10 条。
3. 若首屏 10 条未填满容器（大屏高窗口），自动再取一批，避免"有下一页却没有滚动条"。
4. 全部取完：占位行消失，不再请求。

**流程 9 · 进入服务商设置（列表页）**
1. 点侧栏底部 ⚙ → 右侧主区从聊天切成服务商设置列表页（聊天状态保留，回来还在）；⚙ 高亮。
2. 列表页每行：首字母 icon、名称、模型数、官网链接（点开新标签）、✎、⋯。
3. 「+ 添加服务商」→ 编辑页（空表单）；行尾 ✎ → 编辑页（预填该服务商）。
4. 「返回聊天」→ 回聊天视图。

**流程 9c · 检测连通**
1. 行尾 ⋯ → 抽屉 → 「检测连通」→ 抽屉关闭，行尾短暂 loading（原型省略）→ toast。
2. 成功：「DeepSeek 连通正常，312ms」（`bg-ink` + 勾）。失败：「DeepSeek 连不上：401 api_key 无效」（**`bg-danger`** + 感叹号，文案带原因与下一步）。

**流程 9d · 删除服务商**
1. ⋯ → 「删除」或编辑页右上「删除」→ 确认弹层：「删除「DeepSeek」？」正文「这个服务商下的 3 个模型会一起删掉，模型切换器里也不再有它们。已有会话里的历史消息不受影响。」
2. 危险按钮「删除服务商」→ toast「服务商已删除」；次按钮「先留着」。

**流程 9e · 编辑 / 新增服务商**
1. 编辑页：改基本信息 → 点「拉取模型列表」挑模型（见流程 10）→ 调模型行（标识 / 展示名）→ 点行首单选改默认模型 → toast「默认模型已改为 xxx」。
2. 「保存服务商」→ 校验（字段级 → 清单级：空清单 / 标识重复 / 默认模型不在清单）→ 成功 toast「服务商已保存」并回列表页；失败则字段描边 `border-danger` + 清单下方列错误。
3. 「← 服务商列表」或「取消」→ 回列表（**未保存改动直接丢弃**，见待确认点 10）。

**流程 10 · 拉取模型失败**
1. 上游 401 / 不可达 / 超时（后端统一 502）→ 弹层顶部出现 `bg-danger-soft` 块，标题是上游原因（如「上游返回 401：api_key 无效」）。
2. 已填的连接信息、已手填的模型行**全部保留**；用户可以改 api_key 再拉一次，或直接关掉弹层手填。
3. 手填路径永远可用，不依赖拉取成功。

## 7. 原型说明

- **保真度**：高保真（最终开发按原型 DOM 结构与类名 1:1 实现）。
- **技术栈**：落地栈 = Vue 3 + TS + Tailwind v4 + **`lucide-vue-next`（图标）**；**原型层 = 静态 HTML + 原生 JS + Tailwind 类名**（零框架、零 CDN、零外部请求）。
- **文件**：`docs/deliverables/mvp-ai-chat/02-ui原型.html`（单文件 114KB，样式由 `tokens.css` 编译后内联在 `/* tailwind:start */` 标记块里）。
- **样式怎么来的**：`bash .agents/skills/flow-design-ui/scripts/build-prototype.sh <原型路径>` 把 `docs/设计系统/tokens.css` 用 Tailwind v4 CLI 以 minify 模式编译后写进标记块，幂等可重跑。本项目没有 `package.json` / `node_modules`（Go 项目），编译在 `/tmp/gulu-proto` 沙箱里跑（那里装了 tailwindcss v4 + @tailwindcss/cli），跑完把产物回写。**改完类名必须重跑一次**，截图验的是编译后的产物。
- **三条门禁**：① `build-prototype.sh` 全绿（无外部脚本/样式引用、无 Tailwind CDN、无 `{{ }}`、无 Vue 指令、无 `type="module"`、产物在 `<style>` 内、渲染探针 body 背景 `rgb(248, 248, 247)`）；② 断网双击可用（样式全内联，无任何 http 资源）；③ 禁用 JS 可读（剥掉 `<script>` 后渲染 175KB vs 206KB，差异仅来自 JS 自动补一批会话列表；首屏结构、样式、文字完整，归档为 `chat-1440-nojs.png`）。
- **覆盖范围**：聊天页 6 种状态（默认 / 流式 / 加载骨架 / 空 / 错误 / 无服务商）+ 会话列表 3 种（首屏 10 条 / 加载下一批 / 全部 24 条）× 断点 390·768·1440；**服务商设置 9 种状态**（列表 / 编辑页 / ⋯ 菜单 / 删除确认 / 新增 / 拉取模型 / 拉取失败 / 校验错误 / 空）+ 4 个弹层（编辑标题 / 编辑消息 / 删除会话确认 / 删除服务商确认 / 拉取模型）+ Toast（成功 / 危险两态）。
