# 设计稿（项目级设计系统）

> 项目级文件，放在 `docs/设计稿.md`。
> 由 `flow-design-ui` 首次建立、后续需求增量更新；各需求的 UI 设计读取复用其中的 token 与规范。
>
> **权威分工**：数值的唯一事实来源是 `docs/设计系统/tokens.css`；本稿写**理由、用法、示例**。
> 表内数值必须与 `tokens.css` 逐字一致；两者不一致时以 `tokens.css` 为准，并回头修正本稿。
> 改视觉的顺序：`tokens.css` → 本稿 → 原型与页面。

## 1. 视觉主张

**对话是一份铺满桌面的稿纸，不是聊天软件。** 注意力全部落在文字上：正文 16/28、助手回复无气泡无边框、消息区铺满右侧（只留 48px 内边距，不居中成窄栏）；侧栏、按钮、时间戳一律退到 13px 以下，只用发丝线分节。全页只有一个带底色的内容块——用户消息；输入区做成「上排图标 + 下方输入框」两层，图标行先声明可以长出一排工具，但 MVP 只放一个，不预造空按钮。

为什么：咕噜是单人本地用的长文对话工具（读代码、读长解释），密度和留白比"卡片感"重要；多服务商是它区别于官方客户端的核心，所以模型名必须常驻可见，而不是藏在设置里。

## 2. 参考坐标

| 对标产品 | 借鉴什么 | 不借鉴什么 |
|---------|---------|-----------|
| iA Writer | 正文阅读宽度与行距的克制：单栏、窄行宽、几乎无界面 | 单色到没有状态反馈——它不需要，对话工具需要明确的流式 / 错误 / 禁用态 |
| Bear | 左栏会话的密度与时间戳层级：一行一条、标题截断、时间右对齐 | 标签 / 主题色系统，多一层组织成本，MVP 用不上 |
| Claude.ai | 助手回复的纯文本排版与代码块处理（无气泡、整段可读） | 品牌暖色与卡片化输入区，会把注意力从文字挪到容器上 |

**差异化主张**：让"多服务商"在界面上可见——每条回复都留下模型落款，会话内换模型留一道痕迹。官方客户端做不到，因为它们只有自家模型。

## 3. 色彩

语义命名，**核心 6 个**：neutral（画布/表面/边框）、ink（文本三档）、primary（唯一强调）、danger、success、warning。其余是派生层级。**页面里禁止出现裸色值**，一律走 token。

| Token | 值 | 用途 |
|-------|----|------|
| `--color-canvas` | `#f8f8f7` | 页面底（极浅暖灰，保留稿纸感） |
| `--color-surface` | `#ffffff` | 卡片 / 面板 / 弹层 / 当前会话项 / 输入区 |
| `--color-surface-alt` | `#f0f0ef` | 侧栏底 / 用户消息 / 代码块 / 骨架条 / 表头 |
| `--color-border` | `#e5e5e5` | 发丝分隔线 |
| `--color-border-strong` | `#d1d1d1` | 控件描边 |
| `--color-ink` | `#1a1a1a` | 主文本 / 消息正文 |
| `--color-ink-muted` | `#5b6472` | 次要文本 / 时间戳 / 提示 |
| `--color-ink-subtle` | `#667085` | 占位符 / 禁用 / 图标弱化 |
| `--color-primary` | `#2563eb` | 主操作 / 当前项 / 焦点 |
| `--color-primary-hover` | `#1d4ed8` | 主操作 hover |
| `--color-primary-soft` | `#eff6ff` | 选中项底 / 选区底 |
| `--color-on-primary` | `#ffffff` | primary 上的文字 |
| `--color-danger` | `#c0271f` | 删除 / 错误 |
| `--color-danger-soft` | `#fef2f2` | 错误软底 |
| `--color-success` | `#15803d` | 成功 / 已完成 |
| `--color-success-soft` | `#f0fdf4` | 成功软底 |
| `--color-warning` | `#b45309` | 待处理 / 缺配置 |
| `--color-warning-soft` | `#fffbeb` | 警告软底 |
| `--color-focus-ring` | `#2563eb` | 键盘焦点环 |
| `--color-overlay` | `rgb(26 26 26 / 0.32)` | 弹层遮罩 |

**用色纪律**：强调色只有 primary 一个；语义色只表达状态，不当装饰；灰阶三档，不加第四种。

**对比度（实测，AA 普通字号 ≥ 4.5:1）**：ink/surface 17.40 · ink-muted/surface 5.98（侧栏底 5.25）· ink-subtle/surface 4.97 · primary/surface 5.17 · danger/surface 5.91（danger-soft 上 5.41）· success/surface 5.02 · warning/surface 5.02（warning-soft 上 4.84）· on-primary/primary 5.17。
`ink-subtle` 只用于占位符、禁用态与图标，**不承载正文信息**。

## 4. 字体排印

- **字族与角色**（1 + 1）：
  - 正文 / 界面：`--font-sans` = `"PingFang SC", "Hiragino Sans GB", "Noto Sans SC", "Microsoft YaHei", system-ui, -apple-system, sans-serif`
  - 代码 / 等宽：`--font-mono` = `"SF Mono", "JetBrains Mono", "Fira Code", ui-monospace, monospace`
- **字阶**（字号 / 行高 / 字距）：

| Token | 字号 | 行高 | 字距 | 用途 |
|-------|------|------|------|------|
| `--text-caption` | 12px | 18px | +0.01em | 时间戳 / 模型落款 / 辅助说明 |
| `--text-meta` | 13px | 20px | 0 | 界面控件 / 表头 / 下拉 / 错误卡正文 |
| `--text-body` | 14px | 26px | 0 | 侧栏会话 / 按钮 / 表格 / 表单（默认） |
| `--text-body-lg` | 16px | 28px | 0 | **消息正文**（阅读层，行高 1.75） |
| `--text-title` | 18px | 28px | -0.01em | 会话标题 / 弹层标题 |
| `--text-heading` | 22px | 30px | -0.015em | 预留（页面级大标题） |

- **两套层级**：阅读层 16px，操作层 13–14px。不要用 14px 排消息正文，也不要用 16px 排按钮。
- **行宽 / 行高**：正文行高 1.75，标题行高 1.56。
  - 消息区**铺满右侧**（需求指定）：1440 下正文约 69 中文字/行，仍 < 80 字符硬线，但超过 38 字舒适线——这是"用满屏幕"换来的取舍。
  - 需要窄栏时（长文阅读、表单）用 `--container-content` = 42rem（672px，约 38 中文字/行）；小弹层用 `--container-form` = 32rem。
- **数字**：时间、数量、页码一律 `tabular-nums`（基础层对 `time` 与 `[data-numeric]` 生效）。
- **禁用**：全大写眉标、标题里强调单个词、装饰性小标签。

| **行内激活按钮**（"启用某一条"用） | 两态共用一套骨架：未激活 = `size-7` 纯图标（`text-ink-muted`，hover `bg-surface-alt` + `text-ink`）；已激活 = `h-7 px-2 gap-1.5` + `bg-primary-soft` + `text-primary` + `font-medium` + `text-meta` + **图标 + 文字**（如「激活」）。图标用语义动作（`power`），不是对勾 | 用于"点一下把这一条设为当前"的清单页（服务商、将来的 MCP 服务）。**已激活态不响应 hover**（它是状态，不是动作）；**文字是为了不依赖颜色识别状态**，代价是行宽变化，由 `shrink-0` 吸收；**不给整行加底色**——整行变色是"当前打开的那一项"的语言（会话列表在用） |
| **状态徽标**（行内） | `rounded-xs bg-primary-soft px-1.5 py-0.5 text-caption text-primary`，紧跟主文本之后；同类还有 `bg-success-soft` / `bg-warning-soft` / `bg-danger-soft` 三档 | 只表达"当前状态"，不做可点击按钮；一行最多一个。**若该状态已经由一个按钮的文字态表达，就不要再加徽标**（同一件事说两遍） |
| **顶部提示条**（`Banner`） | 整宽、`border-b border-border`、`bg-warning-soft`、`px-4 py-3 sm:px-8 lg:px-12`，与主区同一套水平内边距；`size-4 text-warning` 图标 + `text-meta text-ink` 一句 + 右侧 `h-8` 描边按钮（可选） | 用于"缺了某个前置条件、功能暂时不可用"；**文案必须说清缺什么 + 怎么补**，按钮文案是动作（「添加服务商」「去选择」）。同一时刻只显示一条：条件互斥的横幅不能叠 |
| **条目卡片行**（`ModelRow`） | `rounded-md` + `border-border` 发丝边 + `bg-surface` + `px-3 py-2`；**单行**＝单选 / 主字段（`font-mono`）/ 次字段 / 删除，控件一律 `h-9`，行高约 54px | 这是"可增删的条目"才配拥有的卡片；字段多于 3 个时不要再往行里加第二排——要么换编辑页，要么把次字段收进展开区；同类卡片 ≤ 8 个，再多就改成表格 |
| Toast | `bg-ink` + `text-on-primary` + `rounded-md` + `shadow-overlay`，底部居中，2s 自动消失 | 文案与触发按钮同一动作同一词 |
| 图标 | **Lucide**（`lucide-vue-next`）：24 网格、纯线性、`currentColor`、`stroke-width="1.5"`、`linecap/linejoin="round"`；尺寸只用 `size-4`（次要场景 `size-3.5`）；图标按钮容器 `size-7` / `size-8` | 图标按钮必须有 `aria-label`；hover 靠 `text-ink-muted → text-ink` + `bg-surface-alt` 表达，不给图标单独上色；**禁止 emoji**、禁止混用第二套图标集 |

## 6. 间距与圆角

- **间距**：4px 基标度（`--spacing: 0.25rem`）。页面里只用 4 / 8 / 12 / 16 / 24 / 32 / 48 步长；13px、18px 这类值视为错误。
- **对齐线**：同一列的多个区块（如会话头 / 消息区 / 输入区）必须共用一套水平内边距，左缘与右缘落在同一列；不要给其中一个单独设内边距。窄屏若需要汉堡按钮，把它放进右侧图标组末尾，别插在标题左边。
  - **主从布局例外**：设置类整屏视图里，头部横跨全宽（仍用同一套内边距），详情内容因左侧多了一列导航而整体右移一个导航宽度——这是主从结构的有意偏移，不算错位。
  - 组件内 padding 8–16px；消息之间 24px；区块之间 24–32px；页面内边距 16px（手机）/ 32px（≥sm）。
- **圆角**：`--radius-xs` 3px（骨架条 / 行内 code / 小标签）、`--radius-sm` 5px（图标按钮 / 菜单项）、`--radius-md` 7px（按钮 / 输入框 / 代码块）、`--radius-lg` 10px（弹层面板 / 卡片）、`--radius-xl` 14px（用户消息 / 输入区容器）、`--radius-full`（圆点）。
- **容器宽度**：`--container-form` 32rem（小弹层）、`--container-content` 42rem（消息阅读栏）、`--container-wide` 84rem（宽表 / 看板，当前未用）。
- **断点**：沿用 Tailwind v4 默认，不改。`lg`(1024) 侧栏常驻 / 以下转抽屉，同时消息区内边距从 32px 变 48px；`sm`(640) 收起表格次要列与输入区提示文案；`md`(768) 再收一列。

## 7. 动效

- 时长 160ms，缓出曲线 `--ease-out-soft`；只动 `background-color` / `border-color` / `color` / `opacity` / `transform`。
- **非用户触发的动效全页只允许一处**（一次进场或一次揭示）。咕噜聊天页目前只有流式生成的三点指示（属加载态，不是装饰），没有"每块淡入上滑"。
- 用户操作反馈保留：弹层进入（160ms）、hover 露出操作按钮（160ms）、Toast 出现。
- 加载态优先骨架屏（`animate-pulse`），不用转圈；`prefers-reduced-motion: reduce` 下所有动画降到 0.01ms。

## 8. 文案基调

- **用用户的语言命名**：界面上写「服务商设置」，不写「provider 配置」；写「重试」，不写「regenerate」（术语口径见 `GLOSSARY.md`，「重新生成」是禁用别称）。
- **主动语态 + 动词**：「写第一句」「保存服务商」「删除会话」，不用「提交」「确定」。
- **同一动作全程同一词**：按钮「重试」→ toast「已重试」；按钮「保存并重发」→ toast「已修改并重发」；按钮「删除会话」→ toast「会话已删除」。
- **错误文案**：发生了什么 + 怎么修。「kimi-k2 调用失败：401，api_key 无效 / 到「服务商设置」更新 Moonshot Kimi 的 api_key，再点重试。这次回复没有写入会话。」——不道歉、不模糊、不甩锅。
- **空态文案**：行动邀请。「这个会话还是空的 / 在下方输入框写第一句，回车发送。当前模型 kimi-k2，随时可以在右上角切换。」+ 按钮「写第一句」。
- **系统替用户做决定时必须说明**：模型回落不写「已切换到 deepseek-chat」（像是用户自己换的），写「**服务商换成 DeepSeek，模型跟着换成 deepseek-chat**」——主语是系统、原因是服务商，用户一眼知道这不是自己点的。
- **禁用术语**：「暂无数据」「操作成功」「系统繁忙」「抱歉」「很遗憾」。

## 9. 反"AI 味"与廉价感记录

**本设计主动避开的套路**（默认不选，需求明确指定时以需求为准）：

1. 奶油米白底 + 高对比衬线 + 陶土色点缀 —— 底色虽是暖灰 `#f8f8f7`，但正文为无衬线、无陶土点缀、无衬线标题，不构成这套组合。
2. 近黑底 + 单一荧光绿 / 朱红点缀 —— 不做深色底（深色只出现在 Toast 与遮罩）。
3. 报纸风：细发丝线 + 零圆角 + 高密度分栏 —— 发丝线只做分隔，圆角与留白都在。
4. SaaS 卡片套：所有内容切成同款圆角卡片 + 同款阴影 —— 助手回复无容器，卡片只在弹层与代码块出现，且无阴影。
5. 模板装饰件：全大写眉标、"A · B · C" 中点串、"词 — 碎片"标签、`#0B0B0B` 冒充黑、小字等宽数据标签、按钮带 "→" —— 一律不用；模型落款是 sans 的 `text-caption`，不是等宽小标签。

**廉价感清单**（出现任意一条即判不合格）：emoji 当图标 · UA 默认表单样式 · 满页 `#ddd` 灰框 · 重投影 · 随机灰阶 · 占位符文案 · 卡片全同款阴影 · 渐变光斑 hero。

**图标三条硬规则**（`lucide-vue-next`）：
1. **必须显式传 `:stroke-width="1.5"`** —— Lucide 默认 2，16px 显示下缩成 1.33px，比设计稿粗一档。
2. **不要用 `absolute-stroke-width`** —— 它让线在任意尺寸都保持 1.5px，16px 图标上显得更粗；只有 32px 以上大图标才考虑。
3. **尺寸靠 class**：`class="size-4"`，不传 `:size`，避免和 Tailwind 打架。

图标与组件的对应关系见 `docs/deliverables/mvp-ai-chat/02-ui设计.md` §2.2。

**正向必备**：每一屏至少有一处有意图的排版处理。本项目的两处是——① 阅读层 16px 与操作层 13–14px 的分家；② 每条助手回复下的模型落款行（多服务商在界面上可见）。全页只把大胆花在这两处，其余保持安静。

**设置类界面的两条原则**（2026-10-23 追加）：① **参数多就换布局，不要挤弹层** —— 弹层适合 ≤8 个字段的一次性表单（重命名 / 编辑消息 / 确认）；② **条目多就分两级** —— 一旦要「一屏看多个条目 + 每个条目还有一堆参数」，就改成主区整屏视图：列表页（行内放状态与操作）→ 编辑页（整页替换、独立滚动、保存栏常驻）。左窄栏 + 右详情只在条目少、每行只有一两个字段时成立。
