# ADR-0012: 服务商设置用「主区视图 + 两级页面」，不引路由、不上全局 store

## 状态

已接受（2026-10-23）

## 背景

服务商设置从"8 行表格 + 4 个字段的表单"长成了"每个服务商：连接信息 4 项 + 一个模型清单（可增删、可拉取、含默认模型）"：

- 弹层（`max-w-content` 672px、`max-h-full`）在 1440×900 下，连接区 + 3 个模型行就把可视区吃满，再加一个模型就得滚；而"边填边对照别的服务商"是这类配置页的高频动作。
- 咕噜是单用户本地工具，**没有路由**（ADR-0002：不引 `vue-router`、不引 Pinia），当前唯一页面是聊天页，`?c=<id>` 只是查询参数。

不决策的代价：要么继续挤弹层（参数一多就得砍功能），要么为一个设置页引 `vue-router` + 路由表 + 懒加载，把单页工具变成"有路由但只有一个真实页面"的四不像。

## 决策

**服务商设置 = 主区的第二个视图（`pane`），内部两级页面（`step`），状态机收进一个 composable。**

```ts
// composables/useSettingsPane.ts —— 6 个方法，不碰数据
const { pane, step, editing,
        openSettings, closeSettings,
        editProvider, createProvider, backToList } = useSettingsPane()
// pane: 'chat' | 'settings'   step: 'list' | 'edit'   editing: Provider | null（null = 新增）
```

- `ChatArea` 与 `SettingsView` 用 `v-if` 互斥；侧栏 ⚙ 与设置页「返回聊天」都只调 `openSettings` / `closeSettings`。
- 列表页 ↔ 编辑页是**整页替换**（不是左窄栏 + 右详情）：列表行要放 icon / 名称 / 模型数 / 官网 / ✎ / ⋯，224px 的窄栏塞不下；编辑页字段多，需要整幅宽度。
- **不引 `vue-router`**、**不引 Pinia**（沿用 ADR-0002）。

## 权衡

| 备选 | 代价 | 为什么没选 |
|------|------|------------|
| 继续用弹层 | 零改动 | 一屏放不下；`max-h-full` 内部滚动 + 保存按钮被顶出视口是这类弹层最烦人的地方 |
| 引 `vue-router`，设置走 `/settings` | 设置页可深链、刷新不丢 | 为一个开关引路由表 + 懒加载 + 守卫；`?c=` 也要一起升级成 `/c/:id`，牵动 `useSelectedFromQuery` 与其 5 条测试用例 |
| 用查询参数 `?pane=settings` 表示设置页（不引路由） | 有深链、零依赖，约 10 行 | 语义上"视图"不是"会话选择"那种可分享的状态；刷新停在设置页对本地工具也没价值，反而让"打开就在设置"变成默认印象 |
| 左导航（`w-56`）+ 右详情的主从布局 | 切服务商少一次点击 | 列表行信息多（官网、模型数、两个操作），窄栏挤；且详情仍需要整幅宽度，等于让详情再窄一截 |
| 抽屉（从右侧滑出） | 保留聊天上下文 | 宽度受限（通常 400–480px），模型行两个输入框 + 删除就满了 |
| 全局 store（Pinia）管 `pane` | 未来多视图好扩展 | 3 个字段的状态引一个 store；`provide/inject` + 一个 composable 足够（ADR-0002 的升级触发条件未命中） |

## 后果

- **正面**：设置页拿到整幅宽度（编辑页一屏放得下连接 + 3 个模型行 + 保存栏）；视图状态机只有一处实现（6 个方法），组件不各自维护 `ref`；没有新增依赖，`CLAUDE.md` 依赖清单不变；未来要引路由时，只需把 `useSettingsPane` 内部换成 `useRouter`，组件层不用改。
- **负面 / 代价**：
  1. **设置页没有深链、刷新会回到聊天**（`pane` 只在内存）。对低频操作可接受；如果你希望"刷新还在设置"，就得走 `?pane=settings` 那条被否掉的路。
  2. 侧栏在设置视图下仍然可见（复用同一份会话列表）——如果哪天要求"设置全屏、隐藏侧栏"，要改的是布局壳而不是状态机。
  3. 视图状态机放在 `App.vue` 注入，`SettingsView` 与侧栏都要 `inject` 它——比 props 隐式，但避免了三层透传。
- **可逆性**：高。加路由 = 换 `useSettingsPane` 内部实现 + 加一张路由表；退回弹层 = 换 `SettingsView` 的宿主容器，组件本身不动。
- **升级触发条件**（写进 §4）：出现**第三个**主视图，或需要跨视图共享"当前页面"时，引 `vue-router`，`pane` → `/settings`、`?c=` → `/c/:id`。
